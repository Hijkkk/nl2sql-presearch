# 模型参数与个性化模板说明

本系统把“生成 SQL 的参数”和“展示查询结论的方式”分开处理。前者影响模型生成查询语句，后者只影响查询成功后如何把已验证的数据解释给用户，不会改变只读安全校验。

## 模型参数

| 参数 | 作用 | 建议 |
| --- | --- | --- |
| 模型 | 选择用于 NL2SQL 和结果解读的模型。 | MVP 演示使用已配置的 Qwen 代码模型。 |
| Temperature | 控制回答随机性。数值越低越稳定，越高越有变化。 | NL2SQL 建议 `0.0-0.2`，默认 `0.05`。 |
| Top P | 控制模型从多大概率范围中选择下一个词。 | 建议 `0.7-0.9`，默认 `0.8`。 |
| 最大输出 Tokens | 限制单次模型输出长度。 | 简单查询 `1024` 即可；复杂 SQL 可设为 `2048`。 |
| SQL 安全校验 | 仅允许只读 `SELECT` / `WITH` 查询，并拦截写入、删除和危险语句。 | 演示和生产场景必须开启。 |
| 返回结果洞察 | 展示系统生成的简短结果提示。 | 可按展示需要开启。 |

## 个性化回答模板

查询执行成功后，系统会把“用户问题、字段名和已验证的前 20 行结果”交给模型生成最终回答。模型被明确限制：不能编造数据，不能输出 SQL、思考过程、耗时或状态。

| 模板 | 适用场景 | 输出特点 |
| --- | --- | --- |
| 精简结论 | 快速问答、演示 | 2 到 4 句，直接回答问题。 |
| 分析解读 | 异常值、比较、趋势 | 突出关键发现和可见异常。 |
| 汇报摘要 | 课程汇报、业务同步 | 以简短汇报形式组织事实。 |

“自定义指令”可追加表达要求，例如：`请用两句话总结，并突出成交量最高的股票。` 它只影响最终回答的文字风格，不会修改 SQL、安全规则或查询结果。

## 会话记忆与缓存

同一会话内再次提交完全相同的问题时，前端会复用该问题已有的回答、SQL 和结果，不再调用模型或数据源，并以“已复用本会话缓存”提示。不同问题仍按正常流程执行，保证结果不会被不相关的旧问题误用。

## 执行详情展示

用户默认看到的是模型基于真实查询结果生成的自然语言答案和结果表格。SQL、模型生成时的技术说明、状态、耗时与返回行数被放入可展开的“查看执行详情”区域，便于演示时解释系统行为，同时避免干扰普通用户阅读。
